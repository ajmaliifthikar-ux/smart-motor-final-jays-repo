## 2025-05-18 - Batching Redis Reads to eliminate N+1 latency
**Learning:** Redis sequential reads (N+1 query pattern) in 'searchKnowledge' and 'getKnowledgeByType' were causing unnecessary network latency. We can optimize N+1 getter functions by using batch 'redis.mget' operations while manually reimplementing inner logic such as try...catch JSON parsing. However, when using `break` statements within loops iterating over flattened batched responses, a linearly incremented index (e.g. `dataIndex++`) will desynchronize.
**Action:** Always prefer 'redis.mget' over sequential 'redis.get' calls inside loops for associated ID/key fetching to reduce connection overhead, ensuring that internal error handling and data transformations are correctly preserved. When mapping flat batched arrays back to nested loops, always use calculated indexes (e.g., `i * array.length + j`) instead of linearly incremented counters to prevent desynchronization on early loop termination.
