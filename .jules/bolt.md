## 2026-04-24 - Expensive Intl Object Instantiation
**Learning:** Repeatedly instantiating `Intl` objects (`Intl.NumberFormat`, `Intl.DateTimeFormat`) within functions or React render loops introduces a performance bottleneck due to excessive garbage collection and setup overhead. Furthermore, extracting the local timezone explicitly via `Intl.DateTimeFormat().resolvedOptions().timeZone` to pass it to `toLocaleDateString` is redundant and wasteful, as `toLocaleDateString()` without arguments natively defaults to the local timezone.
**Action:** Always hoist `Intl.NumberFormat` and `Intl.DateTimeFormat` instances to the module scope as constants to reuse them. For local timezone formatting, rely on `Date.prototype.toLocaleDateString()` natively without arguments to prevent unnecessary object instantiation.
