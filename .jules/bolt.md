## 2025-02-17 - [Intl Formatters and Lazy useState Performance Bottlenecks]
**Learning:** Instantiating `Intl` objects (e.g., `Intl.NumberFormat`, `Intl.DateTimeFormat`) inside functions or render loops introduces massive performance overhead (~60-100x slower) compared to hoisting them. Additionally, passing volatile or expensive expressions like `new Date()`, `Math.random()`, or `uid()` directly into `useState` as initializers forces them to re-evaluate on every render, wasting processing cycles.
**Action:** Always hoist `Intl` formatting object instances to module scope for reuse. When initializing `useState` with values derived from expensive, volatile, or impure operations, use lazy initialization (e.g., `useState(() => Math.random())`) to evaluate the logic only once.
